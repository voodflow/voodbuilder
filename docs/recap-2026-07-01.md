## 2. Fix colori componenti importati (tema vs viola)

### Problema

- Pulsante importato restava **viola** invece del colore brand del sub-tema.
- Override rosso da Style Manager funzionava.
- **Clear background**: editor tornava viola, frontend restava rosso (stile inline `!important` non rimosso).

### Cause

1. CSS componente poteva **fissare** `--color-vp-brand-*` con hex (es. `#6366f1`) sullo scope `.voodbuilder-pasted-component`.
2. `registerVisualStyleTarget` inoltrava lo stile al figlio con `!important` ma **non lo rimuoveva** al clear.
3. `stripBackgroundClasses` rimuoveva le classi `bg-*` senza **ripristinarle** al clear.

### Fix

| File | Modifica |
|------|----------|
| `scripts/compile-component-tailwind.mjs` | Token `--color-vp-*` → `inherit`; rimossi override vp nel CSS compilato |
| `TailblocksThemeTokenMigrator.php` | `stripScopedThemeTokenOverrides()` in `migrateCss()` |
| `GrapesJsPastedComponentNormalizer.php` | Bridge CSS `inherit` in `resolvedCssForStoredHtml()` |
| `components-ui.js` | Bridge tema iniettato nel canvas (`injectComponentCatalogCss`) |
| `tailwind-visual-style.js` | Clear degli stili inoltrati al figlio |
| `theme-tokens.js` | `restoreBackgroundClasses()` + snapshot classi in `data-vb-original-bg-classes` |
| `voodbuilder-grapesjs.js` | Restore classi + rimozione inline al clear background |
